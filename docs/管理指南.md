# Skills 仓库管理指南

## 一次理解三个位置

| 位置 | 作用 |
|---|---|
| GitHub `Fubowen001/cb-skills` | 备份、分享、版本历史 |
| 本机仓库中的 `skills/技能名` | 编辑和检查的源码 |
| Codex 的 `$CODEX_HOME/skills/技能名` | Codex 实际读取的安装副本；未设置 CODEX_HOME 时默认 `~/.codex/skills` |

修改其中一个位置，不会自动同步另外两个。推荐先在仓库改源码，检查通过后提交，再更新安装副本。让 Codex 操作时说明仓库、技能名和同步目标即可。

## 安装和升级

首次安装向 Codex 发送：

> 使用 skill-installer，从 https://github.com/Fubowen001/cb-skills/tree/main/skills/photo-to-3d-diorama 安装这个技能。

升级向 Codex 发送：

> 将本机 photo-to-3d-diorama 与 Fubowen001/cb-skills 的 main 比较。先备份本机安装目录，保留本机配置，合并我做过的修改，再更新并核对文件。

需要固定版本时，在安装请求中指定提交 SHA 或已有标签。不要把本机运行库、权重、路径配置和凭据复制进仓库。已有同名目录不能简单重复首次安装命令当成升级。

## 新增技能

1. 在 `skills/` 下新建独立目录，使用小写字母、数字和连字符，例如 `meeting-notes`。
2. 编写 `SKILL.md`，开头包含 YAML 字段 `name` 和 `description`；name 与目录名相同。
3. 把实际需要的工具、参考和模板放入本技能目录，不复制整个项目。
4. 从仓库根目录执行：

```powershell
python -m pip install -r requirements-dev.txt
python scripts/manage_skills.py catalog
python scripts/manage_skills.py check
```

5. 对改变实际行为的代码运行对应测试或真实的小案例，再提交。自动检查不替代技能效果验收。

不熟悉命令时可以直接说：

> 在 cb-skills 中新增一个叫 meeting-notes 的技能，更新技能目录并检查，验证后提交。

## 修改与同步

日常可新建功能分支，提交后通过 PR 查看改动和自动检查；简单、已授权的修改也可直接提交 main。不要强制覆盖别人或另一个工作副本的新提交。

提交说明应写清改了什么，例如 `fix(photo-to-3d-diorama): isolate batch asset records`。不要把“测试通过”写成“视觉质量保证”。

同步本机前比较本机和仓库版本；如果只有机器路径配置不同，保留该配置；如果技能代码也不同，先合并而非直接覆盖。更新后核对源文件哈希，并在下一轮对话使用。

## 回退与版本

优先用 `git revert <提交SHA>` 创建反向提交，保留历史。需要单独恢复某 skill 时，从目标提交取回 `skills/技能名/`，更新目录、检查并提交；确认后再同步本机。

适合单独发布时使用标签 `photo-to-3d-diorama-v0.2.0` 等。标签示例不表示本仓库已发布该版本；可以从某个提交开始建立自己的版本号。

## 哪些内容提交

提交技能说明、可复用代码、必要模板、合法保留的第三方资源和不含隐私的测试。照片、个人关键点、生成模型、视频、API 配置、缓存、运行库、模型权重和项目验收截图留在项目目录。

`.gitignore` 是防止误提交的辅助，已经被 Git 跟踪的文件不会因为新增忽略规则而自动消失。提交前仍需查看差异。仓库管理脚本会检查常见本机配置、生成物目录和照片转三维技能内的模型/案例文件。

## 自动检查范围

自动检查验证技能入口、名称、描述、本地文档链接、目录一致性、Python 语法和交付规则回归测试；不调用 GPU、不下载三维权重、不上传图片、不消费生成服务。真实推理、Blender 渲染和艺术质量仍需在对应本机任务中验证。
