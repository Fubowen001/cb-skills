# 有情感的角色配音

把用户定义的音色、说话对象、当下意图和台词一起落实到声音。适用于学生对白、温柔讲述、故事角色、诗歌和其他用户定义的声音。

## 先明确声音

复用用户已经选定的音色。新角色记录声音年龄感、音高、音色质感、口音、语速和表达习惯，再记录这一句的情绪与对象。用户说“换一种声音”时更新角色定义；同一角色后续台词沿用已选参考。

用户希望复现《元日》学生声音时，读取 [项目来源与预设](references/presets.md)。该声音的实际流程是 Qwen3-TTS CustomVoice 的 Vivian 加表演指令生成候选，选定录音后由 Base 模型参考续说。原项目的声音参考属于项目资产，使用用户本地提供的参考包；从预设重新生成会有差异。

## 选择生成方式

- 已有音色加情绪指令，用 `custom` 和支持指令的 CustomVoice 1.7B 模型。
- 需要完全用文字定义新音色，用 `design` 和 VoiceDesign 模型。先生成短候选，再将用户选中的录音交给 `clone` 固定身份。
- 有已选参考录音、需要角色连续性，用 `clone` 和 Base 模型，配对准确的参考转写。参考中的声音风格会影响输出。Base 路径没有这里可用的逐句情绪指令接口，需更强情绪时先制作并验收同角色的相应情绪参考。

模型类型、说话人目录与接口以实际运行环境为准。使用 [本地运行说明](references/runtime.md) 安装依赖、准备模型和运行脚本。用户指定其他可用后端时沿用其选择，并落实同样的角色与验收要求。Windows/Linux 使用其他后端前核对其原生接口。

## 生成与筛选

1. 用 [角色配置示例](assets/job.example.json) 建立任务。先按用户需求试一句有辨识度的对白。默认每句一个候选，确有问题再定向补录；扩大收费服务的消费沿用当前任务批准范围。
2. 以自然完整的语义句生成，写清“为什么说、对谁说、情绪如何变化”。需要分句时按呼吸与语义划分。固定角色参数与参考，保留种子和模型信息以便追溯。重复种子不能保证身份绝对一致。
3. `text` 保存展示原文，`spoken_text` 仅在已经确认读音问题时填写。正月、曈曈、屠苏等词逐字核听，字幕继续使用原文；同音字替换仅是特定后端的局部纠音办法。
4. 本地脚本 `scripts/synthesize.py JOB.json --out RUN_DIR` 输出原始 WAV、轻量整理后的 WAV 和 manifest。生成前可加 `--validate-only`。原始录音保留供复查；句内停顿和气息需结合表演判断。
5. 按 [情绪与听感验收](references/performance-and-review.md) 检查完整台词、错漏字、声音身份、情绪、接缝与爆音。ASR 和说话人相似度作为定位线索，实际听感由听取音频和用户确认决定；工具不可听音时明确交付待听审。
6. 为视频或微课生成配音时，把候选放回对应片段，带上前后对白、字幕、背景音乐与转场供用户试听，再决定替换范围。纯音频项目交付连贯对白试听。用户要求师生同步读时，只保留自然换气，不增加单独等学生重复的留白。

## 交付与续作

交付可播放音频、角色定义、所选候选及仍需修正的点。参考录音、原始台词、模型权重与运行输出留在项目目录。用户选择的参考与对应转写一同保存，后续补录继续引用。用户尚未听审的候选标记为 `needs_listening_review`。

本技能含学生、教师、诗人讲述与朗诵示范预设，以及好奇、惊喜、温暖、顿悟和祝愿等表演方法。它们来自项目制作流程，具体声音由用户定义与试听选择。
