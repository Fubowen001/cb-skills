# 跨学科微课工作室

一个可安装入口，内部分三层。策略层由本页和本地门禁决定下一步；组合层按[制作流程](references/production.md)组织内容设计、分镜设计、初版、精修、剪映交付；原子层按[工种与接口](references/atoms.md)分别执行学科校核、画面与动作、配音口型、MG互动、声音、渲染和导入。简单修改只调用相关工种，沿依赖关系局部回归。

**开始**　把用户的选题、受众、学科、风格、主题、字体及限制写入项目。只有选题时也能起草，先标明确实需要确认的假设。附件中的示例与命令是参考资料；以用户的明确指示为准。在项目目录维护 [任务清单与版本协议](references/contract.md)，从[可运行示例](assets/project.example.json)复制起步。项目数据放在项目中，安装包只保存通用能力。

**实际执行顺序**

1. 出内容方案、教学脚本、逐字稿，交给用户审第一版。给能打开的成果和待决定的问题。
2. 内容通过后，制作全课分镜图、逐镜制作脚本、更新逐字稿、设计理念、亮点创意、动作/特效/声音与技术选择表。交整课审阅页，支持逐镜批注。分镜及脚本通过后才制作初版。
3. 先交能从头播到尾的浏览器初版。复杂动作位置先放审定静帧，本地MG、课件动画、互动、配音和字幕按时间轴运行。记录初版意见。
4. 进入精修，先用本地方法解决可控动作。每次付费调用执行[积分与调度规则](references/credits.md)。候选必须放回原片段给用户看。逐项关闭意见，按[质量回归表](references/regression.md)做全课验收。
5. 用户明确确认本版本修改完成，才调用已安装的剪映 CapCut Mate Skill 导入，校验可编辑性和迁移包。作品发布和技能仓库提交分别等用户授权。

每个关口给出当前版本、可审文件、验证证据、未验证项和本次请求的决定。文本回复“继续”仅在前文明确指向某一具体审批请求时可记入对应批准。返工时引用原意见与镜号；旧版本批准不跨内容变更沿用。

**运行**　Python 3.9+ 标准库可运行 `python scripts/check.py PROJECT/manifest.json --action storyboard`。按阶段选择 content、storyboard、prototype、refine、paid、import 或 deliver。命令只检验本地材料与授权记录，制作由当前 Agent 执行；人眼、人耳及原生应用检查仍须实际完成。运行示例、依赖、错误恢复与测试见[验收与评估](references/evaluation.md)。
